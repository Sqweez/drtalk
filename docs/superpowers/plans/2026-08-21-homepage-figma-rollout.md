## Правило движения по плану

1. Работаем только над первым этапом, в котором остались пункты `[ ]`.
2. После фактического выполнения меняем соответствующий пункт с `[ ]` на `[x]`.
3. К следующему этапу переходим только после закрытия всех технических пунктов текущего этапа и визуального подтверждения пользователя.
4. Пункт «Визуально принято пользователем» нельзя отмечать без явного подтверждения пользователя.
5. Проверки делаем минимально необходимыми: сборка, форматирование и точечная техническая проверка. Основную визуальную сверку выполняет пользователь.

## Зафиксированные решения

- [x] Разработка ведется только в теме `drtalk-redesign`; legacy-тема используется лишь как справочник.
- [x] Desktop и mobile из утвержденной страницы Figma считаются источником истины.
- [x] Иконки, изображения и анимации берем из вкладки Components, если ресурс там существует.
- [x] Для light purple background используется `dark` noise; для остальных фонов — `orange` noise.
- [x] Исключение для Problem cards: статический noise не используется, orange noise появляется только в hover/focus-состоянии.
- [x] Интерактивность должна работать с мышью и клавиатурой; touch и `prefers-reduced-motion` учитываются там, где это применимо.
- [x] Не редактируем скомпилированный `dist/output.css` вручную.

## Риски и ограничения

- Figma помечена как готовая на 99%, поэтому возможны небольшие изменения дизайна и контента.
- Бизнес-логика health score пока требует отдельного подтверждения.
- GIF-анимации и крупные растровые ресурсы могут повлиять на производительность; оптимизируем их только при фактической необходимости.
- Существующие shell-тесты не изменяем без отдельного запроса пользователя.
- WordPress core, плагины, backend-интеграции и legacy-тема не входят в этот план.
